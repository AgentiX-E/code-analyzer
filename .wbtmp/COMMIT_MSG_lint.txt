fix(lint): the baseline carries the runner's ceiling, because import/order needs a resolvable alias

**The regenerated baseline was measured on a tree whose workspace packages are not built, and `import/order` only
fires when the `@code-analyzer/*` alias actually resolves.** So this machine found 14 findings in
`packages/intelligence/src/__tests__/cross-repo-e2e.test.ts` and none at all in `pr-review-e2e.test.ts`, while the
runner - which builds first - found **16** and **2**, and the two extra findings in each are the same two rules:

```
cross-repo-e2e.test.ts(10:1)  import/order  There should be no empty line within import group
cross-repo-e2e.test.ts(12:1)  import/order  `@code-analyzer/intelligence` should occur before import of `vitest`
pr-review-e2e.test.ts(10:1)   import/order  There should be no empty line within import group
pr-review-e2e.test.ts(12:1)   import/order  `@code-analyzer/intelligence` should occur before import of `vitest`
```

**Evidence that it is the resolver and not the file**: `eslint` run directly on both files here reports 14 for the
first and nothing for the second, and the twelve `no-unsafe-argument`/`no-explicit-any` findings plus the two
`no-floating-promises` ones are identical on both platforms - only the two alias-dependent rules differ. **The files
are byte-identical; the linter's view of them is not.**

## And the recording is a ceiling, which is what a ratchet's number is

A ratchet fails a file that **exceeds** its recorded count, and improving is always allowed. So recording the
**higher, runner-measured** number is correct: this machine (14 / 0) still passes, and the runner (16 / 2) passes
too. This is the convention the coverage gate already uses - its floors are calibrated on CI because `watcher.ts`
measures 85.18 there and 92.59 here.

**The rule this adds**: `scripts/lint-per-file.js --update` must be run where the workspace packages are built, or
its numbers undercount every file that imports one by alias. Regenerating on an unbuilt tree is the same class of
error as a stale baseline - a measurement of the instrument rather than of the subject.
